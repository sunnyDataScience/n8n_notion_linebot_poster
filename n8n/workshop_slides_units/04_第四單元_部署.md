**節點序列：**
```
[Error Trigger] → [Set 錯誤資訊] → [Notion 寫 Log] → [LINE 通知]
```

**測試方式（故意弄壞它）：**
1. 搭完 Flow C 後按 Test
2. 去 Flow A 故意填一個錯誤的 API Key
3. 觸發 Flow A → 它會報錯 → Flow C 自動接手
4. 檢查：LINE 有沒有收到錯誤通知？Notion Log 有沒有紀錄？

**預期結果：** 故意弄壞它，確認守門員真的會叫你

**預估時間：** 10 分鐘

> **口白提示：** 「故意搞破壞是測試最好的方式。如果你的手機收到 LINE 通知說系統出錯了，恭喜，守門員上線了。」

### Slide 4-5｜部署前 Checklist

**類型：** 清單頁

**標題：** 部署前確認清單 — 少一個都不行

**內容（核取清單）：**

**三條工作流：**
- [ ] Flow A（索引更新）測試通過
- [ ] Flow B（LINE Bot 問答）測試通過
- [ ] Flow C（守門員）測試通過

**Credentials（四把鑰匙）：**
- [ ] Notion API Token
- [ ] Google Drive OAuth
- [ ] Pinecone API Key
- [ ] LINE Channel Access Token + Secret

**環境變數（部署必填）：**
- [ ] `N8N_LISTEN_ADDRESS=0.0.0.0`
- [ ] `WEBHOOK_URL=https://你的Zeabur網域`
- [ ] `N8N_ENCRYPTION_KEY=自訂密鑰`

> **口白提示：** 「一個一個勾。沒有勾完不要部署，不然上去一定出問題。」

| **解法：** 環境變數加上這行 | **解法：** 改成 Zeabur 給你的網域 | **解法：** 到雲端 n8n 重新設定一次 |

### Slide 4-7｜實作導航 — 部署到 Zeabur

**類型：** 實作導航頁

**標題：** 動手時間：部署到 Zeabur

**步驟：**
1. 登入 Zeabur → 建立新專案
2. 選擇 n8n 模板（或 Docker 部署）
3. 設定環境變數（Checklist 上那三個）
4. 等待部署完成（約 2-3 分鐘）
5. 到 n8n 雲端版 → 匯入三條工作流
6. 重新設定 Credentials
7. 更新 LINE Developers 的 Webhook URL → 指向 Zeabur 網域

**最終驗證：**
1. 關掉你的電腦
2. 拿起手機，在 LINE 問 Bot 一個問題
3. 如果 Bot 回答了 → 恭喜，你的 AI 助理 24/7 上線了

**預估時間：** 20 分鐘

> **口白提示：** 「這是今天最關鍵的一步。做完之後，你可以跟朋友說：我做了一個 AI 助理，你加好友試試看。」
