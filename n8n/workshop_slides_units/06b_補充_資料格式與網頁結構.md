## 1. 先搞懂一件事：什麼是「結構化」？

### 生活比喻

想像你收到兩種業績報告：

**報告 A（結構化）：**
```
業務：黃淑芬
客戶：統一企業
金額：816,000
階段：合約審核
```

**報告 B（非結構化）：**
```
黃淑芬上週跟統一的案子進到合約審核了，金額大概八十幾萬，
法務那邊已經在看了，應該月底前會簽。
```

兩份報告講的是同一件事。
但報告 A，程式一秒就能讀懂。
報告 B，程式需要「理解中文」才能處理。

### 結構化 vs 非結構化

| | 結構化資料 | 非結構化資料 |
|---|---|---|
| 定義 | 有固定格式、固定欄位 | 自由格式，沒有固定規則 |
| 程式能直接讀嗎 | 可以 | 需要額外解析 |
| 格式 | JSON、CSV、XML、RSS | HTML、PDF、圖片、影片、自由文字 |
| 比喻 | Excel 表格 | Word 文件 |

> **重點：n8n 最喜歡結構化資料。** 如果你拿到的是非結構化的，第一步就是想辦法把它變成結構化。

## 2. JSON — 現代 API 的標準語言

### 一句話解釋

> JSON 是目前最主流的資料交換格式，幾乎所有現代 API 都用它。

### 長什麼樣

```json
{
  "id": 6,
  "salesRep": "林志明",
  "customer": "台積電",
  "amount": 1500000,
  "stage": "提案中",
  "tags": ["半導體", "資安"],
  "contact": {
    "name": "劉資深經理",
    "phone": "03-5636-0006"
  }
}
```

### 特色

| 特色 | 說明 |
|------|------|
| 可以巢狀 | 物件裡面可以放物件（`contact` 裡面有 `name` 和 `phone`） |
| 可以放陣列 | 用 `[]` 表示多個值（`tags` 有兩個標籤） |
| 人類可讀 | 不像二進位檔，打開就能看懂 |
| 檔案很小 | 沒有多餘的標記，傳輸快 |

### 你會在哪裡遇到 JSON

```
✅ 幾乎所有 API 的回應
✅ n8n 節點之間傳遞的資料
✅ 設定檔（package.json、tsconfig.json）
✅ NoSQL 資料庫（MongoDB）
```

### n8n 對應

- n8n 裡面**到處都是 JSON**，不需要特別轉換
- 如果收到 JSON 字串需要解析：用 **Code 節點** 的 `JSON.parse()`

## 3. CSV — 最老派但最萬用的表格

### 一句話解釋

> CSV 就是「用逗號分隔的純文字表格」，Excel 能開、Google Sheets 能開、記事本也能開。

### 長什麼樣

```csv
id,salesRep,customer,amount,stage
1,林志明,鴻海精密工業,640000,提案中
3,陳建宏,國泰世華銀行,980000,報價中
5,張家豪,矽谷數位科技,900000,成交
6,林志明,台積電,1500000,提案中
```

### 特色

| 特色 | 說明 |
|------|------|
| 超級簡單 | 就是逗號分隔，沒了 |
| 不能巢狀 | 沒辦法像 JSON 那樣放物件裡面的物件 |
| 沒有資料型別 | 全部都是文字，數字也是文字（程式要自己判斷） |
| 萬用相容 | Excel、Google Sheets、任何試算表軟體都能開 |

### CSV 的常見坑

```
⚠️ 欄位裡面有逗號怎麼辦？
   → 用引號包起來："統一企業,食品部門"

⚠️ 欄位裡面有換行怎麼辦？
   → 也是用引號包起來

⚠️ 編碼問題（亂碼）
   → 中文常遇到。UTF-8 是安全選擇，但 Excel 有時候要 BOM
```

### 你會在哪裡遇到 CSV

```
✅ 從 Excel / Google Sheets 匯出的資料
✅ 銀行對帳單
✅ 政府開放資料（data.gov.tw）
✅ CRM 匯出報表
```

### n8n 對應

| 場景 | n8n 節點 |
|------|---------|
| 讀取 CSV 檔案 | **Read Binary File** + **Spreadsheet File** 節點 |
| 把資料轉成 CSV | **Convert to File** 節點（選 CSV 格式） |
| Google Sheets 資料 | **Google Sheets** 節點（自動處理，不用管 CSV） |

## 4. XML — 比 JSON 更囉嗦的老前輩

### 一句話解釋

> XML 做的事跟 JSON 一樣，但用的「標記」比較多，看起來比較囉嗦。

### 長什麼樣

同樣的資料，JSON vs XML：

**JSON 版：**
```json
{
  "salesRep": "林志明",
  "customer": "台積電",
  "amount": 1500000
}
```

**XML 版：**
```xml
<deal>
  <salesRep>林志明</salesRep>
  <customer>台積電</customer>
  <amount>1500000</amount>
</deal>
```

### 為什麼 XML 比 JSON 囉嗦？

```
JSON：  "customer": "台積電"           → 24 個字元
XML：   <customer>台積電</customer>     → 33 個字元

XML 每個欄位都要寫兩次標籤（開頭 + 結尾）
同樣的資料，XML 通常比 JSON 大 30~50%
```

### 特色

| 特色 | 說明 |
|------|------|
| 歷史悠久 | 1998 年發明，比 JSON（2001）更早 |
| 支援驗證 | 有 Schema 可以檢查格式是否正確 |
| 比較囉嗦 | 同樣資料，XML 檔案比 JSON 大 |
| 還是有人用 | 政府、銀行、SOAP API、RSS |

### 你會在哪裡遇到 XML

```
✅ RSS Feed（新聞、部落格更新通知）
✅ 政府系統的 API（電子發票、報稅系統）
✅ 銀行的 SOAP API
✅ 舊系統的資料交換
```

### n8n 對應

| 場景 | n8n 做法 |
|------|---------|
| 收到 XML 回應 | **HTTP Request** 節點會自動解析 XML → JSON |
| 需要送出 XML | **HTTP Request** 節點，Body 選 XML 格式 |
| XML 轉 JSON | **XML** 節點（專門做轉換） |

## 5. RSS — 網站的「最新消息自動推播」

### 一句話解釋

> RSS 是一種用 XML 格式寫的「最新文章清單」，讓你不用一直去網站看有沒有新文章。

### 生活比喻

```
沒有 RSS：
  你每天手動打開 10 個新聞網站，一個一個看有沒有新文章。

有 RSS：
  10 個網站各給你一份「最新文章清單」，
  你用一個工具就能看到所有網站的新文章。
  → 有新文章時，清單自動更新。
```

### 長什麼樣

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>業界新聞</title>
    <link>https://news.example.com</link>
    <description>科技業最新動態</description>
    <item>
      <title>台積電宣布新廠計畫</title>
      <link>https://news.example.com/tsmc-new-fab</link>
      <pubDate>Mon, 24 Mar 2026 08:00:00 +0800</pubDate>
      <description>台積電今日宣布將在高雄建設新晶圓廠...</description>
    </item>
    <item>
      <title>AI 產業 Q1 營收創新高</title>
      <link>https://news.example.com/ai-q1-revenue</link>
      <pubDate>Sun, 23 Mar 2026 10:00:00 +0800</pubDate>
      <description>根據最新統計，AI 相關產業第一季營收...</description>
    </item>
  </channel>
</rss>
```

### RSS 的結構（很固定）

```
rss
 └── channel（頻道資訊）
      ├── title（頻道名稱）
      ├── link（網站網址）
      ├── description（頻道描述）
      └── item（每篇文章，可以有很多個）
           ├── title（文章標題）
           ├── link（文章網址）
           ├── pubDate（發布日期）
           └── description（摘要）
```

### 你會在哪裡遇到 RSS

```
✅ 新聞網站（Yahoo 新聞、TechCrunch、Hacker News）
✅ 部落格（Medium、WordPress）
✅ Podcast 平台（Apple Podcasts 的 feed 就是 RSS）
✅ YouTube 頻道（每個頻道都有 RSS feed）
✅ 政府公告（公開招標、法規更新）
```

### 業務場景的用法

```
場景：監控競品新聞

RSS Feed Trigger（每小時檢查一次）
    ↓ 收到新文章
IF — 標題包含「台積電」或「鴻海」？
    ↓ 是
Slack — 通知業務團隊：「競品有新動態！」
```

### n8n 對應

| 場景 | n8n 節點 |
|------|---------|
| 定時抓 RSS | **RSS Feed Trigger** 節點（自動偵測新文章） |
| 手動讀 RSS | **RSS Read** 節點 |
| RSS → JSON | n8n 自動轉換，每篇文章變成一筆 JSON |

## 6. 四種結構化格式比較

### 一張表搞定

| | JSON | CSV | XML | RSS |
|---|---|---|---|---|
| **長相** | `{ "key": "value" }` | `a,b,c` | `<tag>value</tag>` | XML 的子集 |
| **可讀性** | 好 | 普通 | 囉嗦但可讀 | 同 XML |
| **檔案大小** | 小 | 最小 | 大 | 中等 |
| **能巢狀嗎** | 可以 | 不行 | 可以 | 固定結構 |
| **資料型別** | 有（字串/數字/布林） | 沒有（全是文字） | 沒有 | 沒有 |
| **主要用途** | API、設定檔 | 報表匯出、資料交換 | 舊系統、政府 | 新聞、部落格更新 |
| **現在流行嗎** | 最主流 | 永遠有人用 | 逐漸被 JSON 取代 | 還活著 |
| **n8n 支援** | 原生支援 | Convert to File | XML 節點 | RSS Trigger |

### 用比喻記住

```
JSON  = 現代履歷表（簡潔、有結構、大家都用）
CSV   = Excel 試算表（老派但萬用，什麼軟體都開得了）
XML   = 公文格式（囉嗦但嚴謹，政府愛用）
RSS   = 電子報訂閱（固定格式的更新通知）
```

## 7. HTML — 不是給程式讀的，是給人看的

### 一句話解釋

> HTML 是「給瀏覽器看的排版指令」，不是給程式讀資料用的。資料藏在排版裡面，要自己挖出來。

### 為什麼 HTML 是「非結構化」？

同樣是「台積電的商機資料」：

**JSON（結構化）— 程式直接讀：**
```json
{ "customer": "台積電", "amount": 1500000 }
```

**HTML（非結構化）— 資料藏在排版裡：**
```html
<div class="deal-card">
  <h2 class="customer-name">台積電</h2>
  <span class="deal-amount">NT$ 1,500,000</span>
  <p>這是一筆關於資安防護的提案，目前正在評估階段。</p>
  <img src="tsmc-logo.png" />
  <button onclick="viewDetail()">查看詳情</button>
</div>
```

### HTML 裡面的資料問題

```
問題 1：資料和排版混在一起
  → 「NT$ 1,500,000」是文字，不是數字
  → 你要自己拿掉「NT$」和逗號，才能當數字用

問題 2：沒有固定格式
  → 這個網站用 <span class="deal-amount">
  → 另一個網站可能用 <td id="price">
  → 你得一個網站一個網站去找

問題 3：有很多「不是資料」的東西
  → <img>、<button>、CSS class、JavaScript 事件
  → 這些都是排版和互動用的，不是你要的資料
```

### 怎麼從 HTML 裡挖資料

```
Step 1：找到目標元素的「定位方式」

  CSS Selector（最常用）：
    .customer-name     → class 是 customer-name 的元素
    #price             → id 是 price 的元素
    table tr td:nth-child(3)  → 表格第三欄

  XPath（更精確但更複雜）：
    //h2[@class="customer-name"]
    //table/tr/td[3]

Step 2：用工具把文字內容取出來

Step 3：自己做清理
    "NT$ 1,500,000" → 1500000
```

### n8n 對應

```
HTTP Request 節點（GET 網頁，拿到 HTML）
    ↓
HTML 節點（用 CSS Selector 取出目標資料）
    ↓
Set 節點（清理格式：去掉符號、轉數字）
    ↓
乾淨的 JSON 資料
```

### 實際範例：從網頁抓競品價格

```
HTTP Request
  Method: GET
  URL: https://competitor.example.com/products

HTML Extract
  Extraction Values:
    - Key: productName
      CSS Selector: .product-card h3
    - Key: price
      CSS Selector: .product-card .price

Output:
  [
    { "productName": "企業方案 A", "price": "NT$ 98,000" },
    { "productName": "企業方案 B", "price": "NT$ 156,000" }
  ]
```

## 8. JavaScript 渲染 — 你看到的不等於原始碼裡有的

### 這是爬蟲最大的坑

你在瀏覽器裡看到一個漂亮的表格，上面列了 50 筆商機資料。
你用 HTTP Request 去抓那個網頁，結果拿到的是⋯⋯**空的**。

為什麼？

### 兩種網頁的差異

**傳統網頁（伺服器端渲染，SSR）：**
```
你的請求 → 伺服器 → 伺服器組好完整 HTML → 傳給你

你拿到的 HTML 裡面就有完整的資料。
HTTP Request 一抓就有。
```

**現代網頁（客戶端渲染，CSR）：**
```
你的請求 → 伺服器 → 伺服器只傳一個空殼 HTML + JavaScript 檔案

瀏覽器收到後：
  1. 載入 JavaScript
  2. JavaScript 執行
  3. JavaScript 再去呼叫 API 拿資料
  4. JavaScript 把資料「畫」到畫面上

→ 你在瀏覽器看到資料，但原始 HTML 裡面是空的！
```

### 用比喻解釋

```
傳統網頁 = 你訂了一個便當，打開就能吃
  → 資料已經在 HTML 裡面了

現代網頁 = 你訂了一個料理包 + 食譜（JavaScript）
  → 你要自己按照食譜（執行 JavaScript）才能煮出便當
  → 如果你不煮（不執行 JavaScript），打開只有生食材
```

### 怎麼判斷一個網頁是哪種？

```
方法：在瀏覽器對網頁按右鍵 → 「檢視原始碼」

如果原始碼裡面：
  ✅ 看得到你要的資料 → 傳統網頁 → HTTP Request 就能抓
  ❌ 只看到 <div id="app"></div> → JavaScript 渲染 → 要用其他方法
```

### 常見的 JavaScript 渲染框架

```
這些框架做出來的網站，HTTP Request 抓到的通常是空的：

  React（Meta / Facebook）
  Vue.js（很多台灣公司用）
  Angular（Google）
  Next.js（Vercel）
  Nuxt.js（Vue 生態系）
```

### 遇到 JavaScript 渲染的網頁怎麼辦？

```
方法 1（最推薦）：找到 JavaScript 背後呼叫的 API

  JavaScript 也是透過 API 拿資料的。
  你可以用瀏覽器的「開發者工具 → Network」找到那個 API。
  然後直接用 HTTP Request 打那個 API → 拿到乾淨的 JSON！

  步驟：
    1. 打開瀏覽器 → F12（開發者工具）
    2. 切到 Network 分頁
    3. 重新載入頁面
    4. 在 Network 列表中找 XHR / Fetch 類型的請求
    5. 找到回傳你要的資料的那個 API 網址
    6. 把這個 API 網址貼到 n8n 的 HTTP Request 節點

  這是最乾淨的方法，因為你拿到的是結構化 JSON。
```

```
方法 2：用無頭瀏覽器（Headless Browser）

  讓程式「假裝是瀏覽器」，真的去載入 JavaScript 並執行。
  等頁面渲染完，再抓 HTML。

  就像你請一個人幫你去現場看螢幕，然後把看到的東西抄給你。

  缺點：
    - 速度慢（要載入整個網頁）
    - 佔資源（要跑瀏覽器）
    - 容易被擋（很多網站偵測自動化瀏覽器）
```

```
方法 3：用第三方爬蟲服務

  有些服務幫你處理 JavaScript 渲染：
    - ScrapingBee
    - Apify
    - Browserless

  你只要給 URL，它幫你執行 JavaScript，回傳渲染後的 HTML。
  然後你再用 HTML Extract 節點挖資料。
```

### n8n 對應

| 網頁類型 | n8n 做法 |
|---------|---------|
| 傳統網頁（SSR） | HTTP Request + HTML Extract |
| JavaScript 渲染（CSR）| 方法 1：找背後的 API → HTTP Request（推薦） |
| JavaScript 渲染（CSR）| 方法 2：用第三方爬蟲服務的 API |

### 實際範例：找到 JavaScript 背後的 API

```
場景：你想抓某個 CRM 網頁上的客戶列表，但那是 React 做的

Step 1：打開瀏覽器 F12 → Network → 篩選 XHR
Step 2：重新載入頁面
Step 3：發現有一個請求：
        GET https://crm.example.com/api/v2/customers?page=1&limit=50
        Response: [{ "name": "台積電", "industry": "半導體" }, ...]

Step 4：在 n8n 裡直接打這個 API：
        HTTP Request
          Method: GET
          URL: https://crm.example.com/api/v2/customers?page=1&limit=50
          Headers: Authorization: Bearer your-token

→ 拿到乾淨的 JSON，不需要處理 HTML，不需要無頭瀏覽器
```

## 9. n8n 實戰：不同資料來源怎麼接

### 完整對照表

| 資料來源 | 格式 | n8n 怎麼接 | 難度 |
|---------|------|-----------|------|
| 現代 API（Slack、Notion、HubSpot） | JSON | 專用節點 / HTTP Request | 簡單 |
| 自訂 API | JSON | HTTP Request | 簡單 |
| Google Sheets 匯出 | CSV | Google Sheets 節點 | 簡單 |
| 檔案上傳 | CSV / Excel | Read File + Spreadsheet File | 中等 |
| 政府開放資料 | CSV / JSON | HTTP Request | 簡單 |
| 銀行 / 政府 SOAP API | XML | HTTP Request + XML 節點 | 中等 |
| 新聞 / 部落格更新 | RSS (XML) | RSS Feed Trigger | 簡單 |
| 傳統網頁（有資料在 HTML 裡） | HTML | HTTP Request + HTML Extract | 中等 |
| 現代網頁（JavaScript 渲染） | HTML + JS | 找背後 API / 第三方服務 | 困難 |

### 用業務銷售場景串起來

```
一個業務主管的自動化儀表板：

資料來源 1：CRM API（JSON）
  → HTTP Request → 拿到商機列表

資料來源 2：財務部門的 Excel 報表（CSV）
  → Google Drive → Read File → Spreadsheet File → 拿到營收數據

資料來源 3：產業新聞 RSS（XML）
  → RSS Feed Trigger → 自動收到新文章

資料來源 4：競品網站價格（HTML）
  → HTTP Request → HTML Extract → 抓到競品定價

全部匯整 → Summarize → Google Sheets Dashboard
```

## 常見問題 FAQ

**Q：n8n 收到 XML 要怎麼變 JSON？**
A：HTTP Request 節點通常會自動轉。如果沒有，用 **XML** 節點手動轉換。

**Q：CSV 有中文亂碼怎麼辦？**
A：確認檔案編碼是 UTF-8。如果是從 Excel 匯出的，選「CSV UTF-8」格式。

**Q：怎麼知道一個網站有沒有 RSS？**
A：在網址後面試加 `/feed`、`/rss`、`/atom.xml`。或在原始碼裡搜尋 `application/rss+xml`。

**Q：找到背後 API 但需要登入怎麼辦？**
A：看 Network 裡的請求 Headers，通常會有 `Authorization` 或 `Cookie`。把這些加到 n8n 的 HTTP Request Headers 裡。

**Q：爬蟲被擋了怎麼辦？**
A：常見原因是請求太頻繁、沒帶 User-Agent、或被 Cloudflare 擋。可以加 `User-Agent` Header，或降低請求頻率。但如果對方刻意擋，請尊重對方的決定。

**Q：JSON 和 JavaScript 有關係嗎？**
A：JSON 全名是 **J**ava**S**cript **O**bject **N**otation，語法來自 JavaScript。但現在 JSON 是獨立的格式，所有語言都能用，不限 JavaScript。
