### Slide 3-3｜實作導航 — Drive 路徑

**類型：** 實作導航頁

**標題：** 動手時間：搭建 Drive 索引路徑 (A-1)

**節點序列：**
```
[Drive Trigger] → [Download] → [Extract Text] → [Set]
  偵測新檔案       下載檔案       擷取文字        整理欄位
```

**關鍵設定提示：**
- Drive Trigger：選擇你的「n8n-知識庫」資料夾
- Download：檔案 ID 從 Trigger 的輸出拿
- Extract Text：支援 PDF / DOCX
- Set：統一欄位名稱（title, content, source, doc_id）

**預期結果：** 丟一份 PDF 到 Drive 資料夾 → n8n 自動抓到並擷取文字

**預估時間：** 12 分鐘

> **口白提示：** 「一個節點一個節點慢慢拉。拉完一個就先測試，確認有資料流過去再拉下一個。」

### Slide 3-4｜實作導航 — Notion 路徑

**類型：** 實作導航頁

**標題：** 動手時間：搭建 Notion 索引路徑 (A-2)

**節點序列：**
```
[Notion Trigger] → [Get Page Content] → [Set]
   偵測新頁面          抓取內容          整理欄位
```

**關鍵設定提示：**
- Notion Trigger：選擇你的知識庫 DB
- Get Page Content：用 Page ID 抓完整內容
- Set：統一欄位名稱（和 Drive 路徑一致：title, content, source, doc_id）

**重點：** 兩條路的 Set 節點輸出格式要一模一樣，這樣共用管線才能通用。

**預估時間：** 10 分鐘

> **口白提示：** 「這條比 Drive 路徑簡單，因為 Notion 的資料本來就是結構化的。」

### Slide 3-6｜去重策略

**類型：** 概念頁

**標題：** 為什麼需要去重？

**內容（對比圖）：**

| 沒有去重 | 有去重 |
|---------|--------|
| 同一份文件改了 3 次 | 同一份文件只保留最新版 |
| Pinecone 存了 3 份重複內容 | 用 doc_id + updated_at 判斷 |
| 搜尋結果重複出現 | 搜尋結果乾淨精準 |
| 像 LINE 相簿裡同一張照片存三次 | 每張照片只有一份 |

**去重邏輯：**
```
如果 doc_id 已存在 且 updated_at 沒變 → 跳過
如果 doc_id 已存在 且 updated_at 更新 → 覆蓋
如果 doc_id 不存在 → 新增
```

> **口白提示：** 「去重不做也能動，但搜尋結果會很亂。這是系統品質的關鍵。」

### Slide 3-9｜LINE API 設定提示

**類型：** 設定提示頁

**標題：** LINE 設定 — 三件事搞定

**內容：**

**1. 建立 LINE Channel**
- 到 LINE Developers → 建立 Provider → 建立 Messaging API Channel

**2. 拿到兩個值**
- Channel Access Token（長期）
- Channel Secret

**3. 設定 Webhook URL**
- 格式：`https://你的n8n網域/webhook/line-bot`
- 先用 n8n 本地測試 → 部署後再改成 Zeabur 網域

**踩坑提醒：**
- 記得關閉「自動回覆訊息」，不然 LINE 官方回覆會和 Bot 回覆打架
- Webhook URL 必須是 HTTPS

> **口白提示：** 「LINE 設定比較瑣碎，但只要做一次。照著步驟來，5 分鐘搞定。」
