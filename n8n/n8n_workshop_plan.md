# n8n 自動化工作流實戰工作坊：打造你的 LINE AI 助理

> 不寫程式，拖節點就能搭出一套 AI 知識庫問答系統。
> 改編自「AI First 行動力一日工作坊」核心架構，重構為 8 小時一日工作坊

---

## 課程核心理念

大多數人管理知識的方式是「存進資料夾，然後再也找不到」。這堂課不教你寫程式，而是教你用 n8n 這條自動化流水線，把散落各處的文件和筆記**自動讀完、摘要、索引**，再接上一個 LINE Bot，任何人問一句話就能秒得到答案。

工具會迭代，但**拆解資料流、設計自動化架構、讓系統自己照顧自己**的能力，是不會過時的元技能。

**核心主張：** 自動化不是「讓現有流程加速」，而是「讓你不需要再做這件事」。你還在手動整理文件、回答重複問題，代表流程本身就有問題。

**目標：** 學員在一天結束時，能獨立完成一套「文件自動索引 + LINE Bot 智能問答」的工作流，部署到雲端 24 小時運行，並理解如何將此架構應用於商業場景。

**適合對象：** 大學生社團幹部、專題小組組長、需要管理大量文件的工作者、對 AI 自動化有興趣的零程式背景學習者

**工具鏈：** n8n（工作流引擎）+ Google Drive（檔案型資料來源）+ Notion（結構化知識庫）+ Pinecone（向量搜尋索引）+ LINE Messaging API（使用者入口）+ Zeabur（雲端部署平台）

## 核心框架

### 三條工作流

本課程的所有實作圍繞三條工作流展開，從索引到問答到監控形成完整迴路：

| Flow | 功能 | 觸發條件 | 輸出 |
|------|------|----------|------|
| **Flow A：索引更新** | 雙入口自動索引 | Drive / Notion 新增或更新 | Pinecone 向量 + Notion 索引紀錄 |
| **Flow B：問答服務** | LINE Bot 智能問答 | 使用者 LINE 訊息 | AI 回答 + 來源連結 |
| **Flow C：守門員** | 錯誤監控 + 自動補索引 | 錯誤觸發 / 定時排程 | 錯誤通知 + 自動重試 |

**架構口訣：** 索引兩條路進去（Upsert），問答一條路出來（Query），守門員盯著不讓它壞。

### 資料分層架構

| 元件 | 角色 | 比喻 |
|------|------|------|
| Google Drive | 原始資料倉庫（入口 1） | 社辦鐵櫃 |
| Notion | 結構化知識庫（入口 2） | 社團共筆 |
| Pinecone | 向量索引 | 什麼都知道的老鳥學長 |
| n8n | 工作流引擎 | 自動化實習生 |
| Zeabur | 雲端託管 | 讓實習生 24 小時不下班的宿舍 |

### 自動化應用四層次

```
Level 4：智能代理 ——— Bot 自主回答 + 守門員自動偵錯補索引
Level 3：流程自動化 ——— n8n 串接工具，資料進來自動處理
Level 2：工具增強 ——— 用 Notion 整理、Drive 分類，仍需人工維護
Level 1：手動操作 ——— 每次人工搜尋、複製貼上、回覆問題
```

## 課程大綱（8 小時）

### 第一單元 (09:00 - 10:20)：知 — 自動化認知升級與架構思維

> 你花最多時間的，不是做事。是找東西，還有回答別人問過的問題。

**主題：** 建立自動化優先思維，理解資料分層架構與工具角色定位。

**目標：** 學員能辨識自動化四個層次，建立資料分層架構的全局觀，理解每個工具「為什麼在這裡」。

**內容：**

1. **觀念破冰：你不是在寫程式，你是在搭流水線**
   - 從「人工處理」到「自動處理」的跳級思維：找資料 15 分鐘的事，3 秒就搞定
   - MVP 思維：能跑比完美重要
   - 現場提問：「你們社團或專題的資料現在放在哪？」

2. **自動化應用的四個層次**
   - Level 1 手動操作 → Level 2 工具增強 → Level 3 流程自動化 → Level 4 智能代理
   - 今天的目標：從 Level 1 一路做到 Level 4

3. **資料分層架構**
   - 五個元件各自的角色定位：Drive（鐵櫃）→ Notion（共筆）→ Pinecone（老鳥學長）→ n8n（實習生）→ Zeabur（宿舍）
   - 系統全景：兩條入口匯入 Pinecone，LINE Bot 統一查詢

4. **Demo：完成品展示**
   - 講師現場在 LINE 傳訊息「去年迎新的場地在哪裡租的？」，Bot 3 秒內回覆答案 + Notion 連結
   - 讓學員知道今天結束時自己也能做到

**實作活動：** 每位學員選定主題場景（社團交接 / 課堂筆記 / 專題管理 / 打工 SOP），在 Drive 建立監控資料夾並上傳 2-3 份檔案，在 Notion 建立知識庫 DB 與索引紀錄 DB。

### 第二單元 (10:30 - 12:00)：用 — n8n 節點工具箱與工作流設計

> n8n 的畫布就像 Scratch — 不是寫程式碼，是拖方塊、連線、填欄位。

**主題：** 掌握 n8n 的六大節點分類，動手搭出第一條工作流。

**目標：** 學員能用六大節點理解 n8n 的能力邊界，完成 Credentials 設定，獨立搭出「Notion 觸發 → 自動處理」的簡易工作流。

**內容：**

1. **n8n 介面導覽**
   - 畫布、節點面板、執行紀錄、Credentials 設定
   - 你在搭樂高，不是寫程式

2. **六大節點分類（用點餐 App 當比喻）**

   | 節點類型 | 功能 | 點餐 App 類比 |
   |----------|------|---------------|
   | **Trigger** | 啟動工作流 | 客人按「送出訂單」 |
   | **Control** | 分流與邏輯判斷 | 「內用還外帶？」 |
   | **Data** | 格式化、重組資料 | 印出明細 |
   | **Integrations** | 串接第三方工具 | 通知廚房、叫外送員 |
   | **AI/RAG** | LLM 與 Embeddings | AI 店員推薦餐點 |
   | **Observability** | 日誌與通知 | 出餐紀錄 + 客訴系統 |

3. **Credentials 設定實戰**
   - 手把手設定 Notion API、Google Drive API 授權
   - 這一步最容易卡關，但只要設定一次就好

4. **工作流設計思維**
   - 如何把自動化需求拆解成節點序列
   - 從「我想要什麼結果」到「哪些節點能組合出來」
   - 何時該用 IF 分流、何時不該（過度設計的陷阱）

**實作活動：** 搭建第一條工作流 — 在 Notion 知識庫新增一筆「模擬社團文件」→ Notion Trigger 偵測到 → Set 節點整理欄位 → 輸出確認訊息。體驗「我在 Notion 打字，n8n 那邊就自動動了」的感覺。

**工具實作：** n8n、Notion API、Google Drive API

### 第三單元 (13:00 - 14:30)：做 — 雙入口索引管線與 LINE Bot 實作

> 不管資料從哪邊進來，AI 都自動幫你讀完、摘要、索引。以後任何人問，系統 3 秒找到答案。

**主題：** 搭建完整的 Flow A（雙入口索引）與 Flow B（LINE Bot 問答）。

**目標：** 學員完成從「丟檔案進去自動索引」到「LINE 問答秒回答」的完整迴路。

**內容：**

1. **Flow A：雙入口索引管線**
   - **Drive 路徑（A-1）：** Drive Trigger → Download → Extract Text → Set normalize fields
   - **Notion 路徑（A-2）：** Notion Trigger → Get Page Content → Set normalize fields
   - **共用管線：** 兩條路匯合 → LLM 生成 summary + tags + chunks → Embeddings 向量化 → Pinecone Upsert（帶 metadata）→ Notion 索引紀錄寫入 INDEXED
   - 不管來源是 Drive 還是 Notion，到共用管線時格式已統一

2. **去重策略**
   - 用 doc_id + updated_at 判斷是否需要重新索引
   - 沒有去重，Pinecone 裡就會有重複內容，搜尋結果會重複出現

3. **Flow B：LINE Bot 問答**
   - Webhook 接收 LINE 訊息 → Pinecone similarity search（topK）→ LLM 生成帶來源連結的回答 → HTTP Request 呼叫 LINE Reply API
   - LINE API 速率限制與重試策略

4. **Vibe Coding 教學法**
   - 用固定 Prompt 範本讓 AI 產出「節點清單 + 欄位 mapping」，學生照著拉節點就能動
   - 降低門檻：不需要從零思考每個欄位怎麼填

**實作活動：** 搭建 Flow A 並測試兩條路徑（Drive 丟 PDF 自動索引 + Notion 新增記錄自動索引），搭建 Flow B 並用自己手機 LINE 問一個知識庫相關問題，確認 Bot 秒回答案。到 Notion 索引紀錄頁確認兩筆資料都變成 INDEXED。

**工具實作：** n8n、Google Drive、Notion、Pinecone、LINE Messaging API

### 第四單元 (14:40 - 16:00)：部署 — 守門員上線與雲端部署

> 做出來不算數，關掉電腦它還能跑才算。

**主題：** 建立錯誤監控機制，將 n8n 部署到 Zeabur 雲端。

**目標：** 學員完成 Flow C（守門員），將系統部署到 Zeabur，擁有一個關掉電腦仍活著的 LINE AI 助理。

**內容：**

1. **部署前準備**
   - 三條工作流完整性盤點（Flow A / B / C）
   - Credentials 清單確認：Notion API、Google Drive API、Pinecone API、LINE Channel Token
   - 環境變數整理：哪些值必須在雲端重新設定

2. **Flow C：守門員流程**
   - Error Trigger → 寫 Notion Log DB → LINE 通知（壞了馬上知道）
   - Cron 每晚：找 status=NEW 或 last_indexed_at 過期 → 重跑 Flow A（漏掉的自動補上）
   - Cron 每週：抽樣驗證（用熱門問句測試檢索品質）

3. **Zeabur 部署實戰**
   - 從本地到雲端的完整部署流程
   - 必踩的坑：`N8N_LISTEN_ADDRESS=0.0.0.0`（避免 502）、`WEBHOOK_URL` 設定正確網域（LINE callback 必須對）
   - Credentials 雲端重新授權

4. **部署後驗證**
   - 功能驗證：三條 Flow 是否正常觸發
   - Webhook 驗證：LINE Bot callback URL 是否指向 Zeabur 網域
   - 常見問題排除：502 Bad Gateway、Webhook 無法連線、Credentials 遺失

**實作活動：** 搭建 Flow C 的 Error Trigger 並故意觸發錯誤確認通知送達，將 n8n 部署到 Zeabur，關掉電腦後用手機 LINE 問 Bot 確認還活著。學員互加彼此的 LINE Bot 好友互相測試。

**工具實作：** n8n、Zeabur、LINE Messaging API

### 第五單元 (16:10 - 17:10)：商業化 — 自動化流程再造與應用擴展

> 技術只是手段，解決問題才是目的。

**主題：** 建立自動化流程再造思維，掌握將成果應用於真實商業場景的策略。

**目標：** 學員能評估自動化專案的應用價值，找到最高 ROI 的擴展方向，設計基本的商業化策略。

**內容：**

1. **自動化流程再造思維**
   - 不是「把現有流程加自動化」，而是「用自動化重新設計流程」
   - 流程再造三步驟：拆解 → 重組 → 驗證
   - 效率對比：人工回覆 30 個重複問題 = 150 min，Bot 秒回 = 10 min（15 倍）

2. **應用場景延伸**
   - 同一套架構，換個場景就能再做一個
   - 企業知識庫（降低新人訓練成本）、客服自動化（降低人力 80%）、教育培訓（AI 助教）、法務合規（合約摘要與檢索）
   - **【Demo】請假流程自動化** — 表單驅動的審批流程，展示同一套工具鏈如何處理非 RAG 場景
     - LINE 送出請假申請 → n8n Webhook 接收 → 寫入 Notion 請假紀錄 DB → IF 判斷天數 > 3 天 → 主管 LINE 審批通知 → 審批結果回填 Notion
     - 共用今天學過的元件：LINE Webhook、Notion DB 寫入、IF 分流、LINE 推播通知
   - **【Demo】財會表單串接** — 定時匯總型流程，展示 Cron 排程與報表自動化
     - Notion 費用表單送出 → n8n Trigger 偵測 → 格式化欄位 → 寫入 Google Sheets 帳本 → 月底 Cron 自動匯總當月支出 → LINE 推播月報摘要給財務負責人
     - 共用今天學過的元件：Notion Trigger、Set 格式化、Cron 排程、LINE 推播通知

3. **Go-to-Market 策略思考**
   - 你的系統解決了誰的什麼問題？
   - 三種商業模式：客製化建置（一次性）/ SaaS 月費（訂閱制）/ 顧問服務（培訓費）
   - 成本結構：API 費用、雲端主機、維護人力

4. **自動化專案優先序框架**
   - 影響力 × 可行性矩陣
   - 過度自動化的陷阱：不是什麼都該自動化
   - 企業導入的實務策略：從試點到全面推廣

**實作活動：** 學員為今天的系統撰寫一頁式應用企劃 — 目標用戶、核心價值主張、獲利模式、Go-to-Market 策略、30 天擴展計畫。
